# 记忆体架构 V1.2 · 上下文导入 + 架构可扩展

> 基于 V1.1，**新增两个能力**，其余规则不变。
> 适用：任何基于 DSH（DeepSeek Harness）的 AI 助手实例。

---

## 一、这次加了两件事

| # | 能力 | 解决什么 |
|---|---|---|
| **A** | **上下文导入（Context Import）** | 那些"只有会话上下文、没有记忆架构"的 DSH 用户，可以把历史对话**整理成记忆文件**，先审阅再决定接不接入 |
| **B** | **架构可扩展（Extensible Files）** | 记忆文件不再写死七个，**留出编号区间给 AI 自建按需文件**（如 `60-生活.md`） |

---

# 特性 A · 上下文导入

## A1. 场景

很多 DSH 实例只有一堆会话记录，没有 `~/.dsh/memory/`。
它所有的"记忆"其实就是**这些会话的上下文** —— 换会话就忘了。

**要做的**：把上下文**读出来 → 按记忆架构分类 → 生成记忆文件草稿 → 用户先审 → 再合并**。

**核心原则：不是自动写入，是"生成草稿 + 人工审阅 + 用户拍板"。**

## A2. 数据来源

DSH 的会话文件：

```
~/.dsh/sessions/--<工作区转义>--/<session-uuid>/session.v4.jsonl.zstd
```

- **zstd 压缩的 JSONL**：一行一个事件
- **Python 3.14 自带 `compression.zstd`**，不需要额外装库
- 事件类型（实测）：`user/message`、`assistant/message`、`tool/call`、`tool/result`、
  `turn/start`、`step/start`、`session/title` 等

**关键：两种消息的正文位置不一样**
```
user/message       → data.content[]              （元素 type="text"）
assistant/message  → data.message.content[]      （混着 type="reasoning" / "tool-call"，只取 "text"）
```
**这是最容易踩的坑**：只读 `data.content` 的话，助手消息一条都读不到。

## A3. 抽取策略（关键：去噪）

**只要三类信息**：

| 保留 | 丢弃 |
|---|---|
| 用户说的话 | `<system-reminder>` 块、运行时上下文（cwd/权限快照）|
| 助手消息里的**纯文本结论** | `reasoning`（思考）、`tool-call`（工具调用）|
| 报错原文、命令、路径、数值 | `tool/result` 原始输出（除非是报错）|
| — | `<skill_content>` 技能正文、渠道尾巴（如 `[渠道：微信]…`）|
| — | 过程性开场白（"我先看看""让我读一下"）、确认语（"好的""收到"）|

## A4. 归类规则

| 内容类型 | 归到 |
|---|---|
| 用户自述的事实（姓名、年龄、职业、家庭、习惯、偏好、边界） | `10-主人.md` |
| 正在做的事、项目、进度、机器/工具环境 | `20-项目与工作区.md` |
| 明确的要求、禁止、长期约定、红线 | `30-约定.md` |
| 踩过的坑 + 正确做法 + 报错原文 | `40-教训.md` |
| 里程碑事件（带日期） | `50-时间线.md` |
| 无法归类 / 太短 / 过期 | `90-遗忘.md` |
| 每条的一句话摘要 | `00-索引.md` |

**必须按角色区分**（否则助手的工作汇报会被误判成"约定"）：

| 角色 | 规则 |
|---|---|
| **助手** | 含"报错/失败/坑/根因/修复" → `40`；其余 → `20` |
| **用户** | 含"不要/必须/记住/一律/红线" → `30`；含"我叫/我的/生日/家里/喜欢/讨厌" → `10`；含"上线/发布/立项/里程碑" → `50`；太短（<12 字）→ `90`；其余 → `20` |

**每条必须带来源**：`· 来源：<会话前缀> @ YYYY-MM-DD`（可追溯，便于核对）。
**不确定的标 `（待确认）`，不许编造。**

## A5. 流程（五步，人工在环）

```
① 选会话         指定 session id / "全部" / 某时间范围
      ↓
② 抽取 + 去噪     读 zstd → 解析 JSONL → 只留用户话 + 结论 + 报错/命令/数值
      ↓
③ 分类 + 生成     按 A4 规则生成各文件草稿
      ↓
④ 输出到预览目录  ~/.dsh/memory-import-preview/<时间戳>/
      ↓
⑤ 用户审阅后合并  "可以"→ 并入正式 memory（先打快照）；
                   "只留一部分"→ 按指令挑；
                   "不要"→ 整个预览目录丢弃
```

**绝不直接写进 `~/.dsh/memory/`** —— 必须先落到预览目录。

## A6. 安全与质量

| 项 | 要求 |
|---|---|
| **只读** | 只读会话文件，不改写、不删除原会话 |
| **不覆盖** | 目标已有记忆时合并而非覆盖（冲突进「待确认」） |
| **可回滚** | 合并前先打记忆架构快照 |
| **隐私** | 预览文件可能含敏感信息 → 导入报告里列「疑似敏感项」清单，提示审阅 |
| **质量校验** | 每条有来源；索引每条一句话；总条数合理（不要把 3 句话的对话生成 200 条） |

## A7. 实测（Python 3.14 / 16 MB 会话）

| 指标 | 数值 |
|---|---|
| 会话大小 | 16 MB（zstd）|
| 有效事件 | 1312 条 |
| 耗时 | **约 70 秒**（zstd 解压占大头）|
| 产出 | 6 个草稿文件 + 索引草稿 + 导入报告 |

**分类分布（典型）**：`20-项目` 最大（默认桶），`40-教训` 次之，`30-约定` 最少。

## A8. 已知局限（必须人工审阅）

1. **分类是启发式**，不是语义理解 —— `20-项目` 是默认桶
2. **压缩摘要会被当成用户消息**（如 `## Primary Request and Intent…`）—— 内容有价值但需去重
3. **不判断时效性** —— 旧状态可能已过期
4. **不替代整理** —— 只负责"把上下文摊开"，合并前必须人工删减、归并、补索引

# 特性 B · 架构可扩展

## B1. 为什么要扩展

固定七个文件的问题：**主题一多就塞不下**。
比如"生活日常""健康""技能与工具"这类内容，硬塞进 `10-主人` 会撑爆，也不利于按需读取。

## B2. 编号规则（固定骨架 + 可扩展区）

| 编号 | 用途 | 谁建 | 上限 |
|---|---|---|---|
| `00-09` | **常加载**（索引等）| 架构固定 | 索引 ≤150 行 |
| `10` | 主人档案 | 架构固定 | ≤1000 行 |
| `20` | 项目与工作区 | 架构固定 | ≤1000 行 |
| `30` | 约定与红线 | 架构固定 | ≤1000 行 |
| `40` | 教训 | 架构固定 | ≤1000 行 |
| `50` | 时间线 | 架构固定 | ≤1000 行 |
| **`60-89`** | **⭐ 扩展按需文件（AI 可自建）** | AI 决定 | 每个 ≤1000 行 |
| `90` | 遗忘区 | 架构固定 | 不限 |

**命名**：`<两位编号>-<主题>.md`，例 `60-生活.md` / `61-健康.md` / `62-技能与工具.md`

## B3. AI 什么时候可以自建（判断标准）

**满足任意一条即可考虑**：

1. 某主题条目 **>50 条**，塞在原文件里已影响阅读
2. 某主题在原文件占比 **>30%**
3. 检索时**频繁在两个文件间跳**
4. 用户明确说「这类东西单独记」

**不建**：<20 条的临时话题；只为了整齐；已在遗忘区的旧内容。

## B4. 建新文件的强制动作（四条，缺一不可）

1. **`00-索引.md` 加一行**：`- （一句话）→ 60-生活.md`
2. **`AGENTS.md` 文件表里登记**（否则下次会话不知道它存在）
3. **`50-时间线.md` 记一笔**：`YYYY-MM-DD：新增 60-生活.md（原因：…）`
4. **文件头写三行**：主题、上限、建立原因

## B5. 防膨胀

- **扩展文件 ≤6 个**（`60-89` 最多用 6 个）
- 每个 ≤1000 行
- 连续 **30 天没被读过** → 内容并入相关文件或进 `90-遗忘`，**删掉空壳**

## B6. 撤回机制

```
快照回滚到新增之前
或：内容搬进 90-遗忘 → 删文件 → 索引与 AGENTS 删登记 → 时间线记一笔
```

# 三、变更汇总（V1.1 → V1.2）

| # | 项 | V1.1 | **V1.2** |
|---|---|---|---|
| 1 | 文件数量 | 固定 7 个 | **7 个固定 + 最多 6 个可扩展** |
| 2 | 新增文件权限 | 无 | **AI 可按标准自建（60-89 区间）** |
| 3 | 上下文导入 | 无 | **会话 → 记忆草稿 → 人工审阅 → 合并** |
| 4 | 导入安全 | — | 只读、先出预览、不覆盖、先打快照 |
| 5 | 导入质量 | — | 每条带来源、标待确认、禁止编造 |

**不变**：加载策略、遗忘机制（30 天未提及）、⭐常青、每月体检、架构快照、四重备份、写入规则、三不。

# 四、一句话

> **V1.2 让这套架构从"自己的"变成"能帮别人的"：**
> **能迁入存量上下文（A），也能自己长出新的记忆文件（B）。**
