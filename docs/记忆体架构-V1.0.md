# 记忆体架构 V1.0

> 第一版架构：七文件 + 索引分层 + 遗忘区 + 架构快照 + 四重备份。
> 本文件为**通用版**，不含任何个人信息。

---

## 一、一句话概括

**7 个文件 + 1 份人格 + 4 层备份 + 1 个遗忘区。**
开局只读索引，细节按需，过期不删只不加载。

---

## 二、文件清单

| 文件 | 上限 | 开局读？ | 职责 |
|---|---|---|---|
| `AGENTS.md`（在 memory 同级）| **≤200 行** | ✅ 每轮注入 | 人格本体：说话方式、记忆规则、边界 |
| `00-索引.md` | **≤150 行** | ✅ 开局必读 | 记忆地图，每条一句话 + 指向文件 |
| `10-主人.md` | ≤1000 行 | 按需 | 这个人：档案、习惯、偏好、在意的事 |
| `20-项目与工作区.md` | ≤1000 行 | 按需 | **当前状态**：机器、工作区、在办的事 |
| `30-约定.md` | ≤1000 行 | 按需 | 长期约定与红线 |
| `40-教训.md` | ≤1000 行 | 按需 | 踩过的坑与正确做法 |
| `50-时间线.md` | ≤1000 行 | 按需 | 大事记（只记里程碑）|

**定额参考**：常加载（AGENTS + 索引）约 6k tokens；全量约 2 万；遗忘区约 1.6 万。
**这些数字不是标准，是"别失控"的参照。**

## 三、加载策略（省 token 的核心）

```
会话开始
  ├─ 注入 AGENTS.md（固定成本）
  ├─ 读 00-索引.md（一次）
  └─ 按话题按需读 10/20/30/40/50 中相关的一两个
       ↑ 绝不"全量加载"

查旧事时
  └─ 才翻 90-遗忘.md
```

**铁律**：不要一上来把所有记忆文件读进上下文——那等于自己制造一次压缩。

## 四、四条机制

### 1. 索引分层

- 索引只写**一句话 + 指向**，不写摘要段
- 摘要、背景、细节都在对应文件
- 目的：知道"东西在哪"，但不为此付全价

### 2. 遗忘机制（不删除，只不再加载）

**规则**：失效 / 过期 / 已完成 → **原文搬进 `90-遗忘.md`**，索引删掉指向行，**文件永不删除**。

**为什么**：既省 token（不加载），又保住原话与细节。**省 token ≠ 丢信息。**

**归档必带**：日期 + 原因。

**整理顺序**：**先整体归档 → 再重写当前状态**，不许先删后写。

### 3. 架构快照

**触发**：新增/合并文件、改加载规则、大压缩——任何架构改动。

**产物**：
- `记忆架构-v<N>-<日期>.md` —— 改了什么、为什么、怎么回滚
- `memory-v<N>-<日期>.zip` —— 当次全部记忆文件 + AGENTS.md 原件

**回滚**：解压覆盖 `memory/` 与 `AGENTS.md`，再跑一次备份。

### 4. 四重备份

| 层 | 位置 | 防什么 |
|---|---|---|
| 现役 | `~/.dsh/memory/` | — |
| 主副本 | 同机另一路径 | 误删 |
| 异盘 | **另一块物理盘** | 单盘故障 |
| 异地 | 云笔记 / git 私库 | 整机丢失 |

- 改完记忆立即备份；每日定时跑一次
- 脚本保护：源文件少于 N 个拒绝备份

## 五、写入规则

| 发生什么 | 写到哪 |
|---|---|
| 偏好 / 习惯 / 好恶 / 边界 | `10-主人.md` |
| 有长期影响的决定、约定、红线 | `30-约定.md` |
| 踩坑并解决 | `40-教训.md` |
| 新项目 / 工作区 / 状态变化 | `20-项目与工作区.md` + `50-时间线.md` |
| 用户说「记住」「记一笔」 | 必须落盘，并回一句存到哪 |
| 新条目 | **先在索引加一行** |

**三不**：不编造用户事实（不确定标「待确认」）；不把推测写成结论；不加用户没说过的偏好。

## 六、压缩规则（V1.0 原版）

- 单文件超 **150 行** → 整理一次
- 整理顺序：**归档 → 重写**
- 保留项：**用户原话、路径、命令、报错原文、数值**
- 只删自己写的记忆；**永不删用户给的原话和文件**

## 七、已知局限

| 问题 | 说明 |
|---|---|
| 只有"存档"，没有"回忆" | 没有检索层，靠 agent 按需读 |
| 没有经历层 | 记的是事实/项目/约定，没有"我今天做了什么" |
| 没有生命周期 | 写进去就一直在（直到被遗忘规则归档） |
| 靠人肉判断 | 什么该留、什么该归档，仍是判断而非算法 |

这些是 V1.1 及后续版本要解决的。
