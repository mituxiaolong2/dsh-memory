## 一、V1.4 改了什么

| 变化 | V1.3 | **V1.4** |
|---|---|---|
| 怎么找记忆 | 读 `00-索引.md` → 凭联想翻文件 → **读整个文件** | 先检索 → 只读 **top-3 命中块** |
| 检索算法 | 无 | **BM25（0.4）+ 语义向量（0.6）** 混合 |
| 向量模型 | 无 | `bge-base-zh`（98 MB，ONNX，**CPU**）|
| 上下文成本 | 一次 3 万字 | 一次 **300–450 字**（省约 99%）|
| 遗忘区 | 靠我自觉不读 | 检索器**默认跳过** `90-遗忘.md` |

## 二、为什么要这一层

长上下文不便宜，所以不能"全读"，只能"按需取回"——和 NInfer/KVMem 的思路同构：

| 推理引擎 | 记忆体 V1.4 |
|---|---|
| 常驻窗口（sink）| `AGENTS.md`（每轮注入）|
| 显存 KV 池 | 检索命中的 top-3 块 |
| 主机 KV | 其余记忆文件（不读）|
| 内容打分检索 | BM25 + bge-base 混合打分 |
| 超池静默错 | 检索没命中 → 靠脑补（同样危险）|

## 三、工具

```powershell
# 检索（默认混合）
python -X utf8 $DSH_TOOLS\launcher\memory_bm25.py -q "关键词" --top 3
# 只要词面匹配（快，不加载向量）
python -X utf8 $DSH_TOOLS\launcher\memory_bm25.py -q "关键词" --bm25-only
# 记忆体检
python -X utf8 $DSH_TOOLS\launcher\memory_audit.py
```

| 组件 | 位置 |
|---|---|
| 检索主体 | `$DSH_TOOLS\launcher\memory_bm25.py` |
| 向量子模块 | `$DSH_TOOLS\launcher\memory_vector.py` |
| 体检器 | `$DSH_TOOLS\launcher\memory_audit.py` |
| 向量模型 | `$DSH_TOOLS\models\bge-base-zh\`（98 MB）|
| 索引缓存 | `~/.dsh/cache/memory-bm25.json` |
| 向量缓存 | `~/.dsh/cache/memory-vec-bge-base-zh.npz` |
| **命中日志** | `~/.dsh/cache/memory-hits.jsonl`（每次检索命中了哪个文件哪一行）|

## 五、已知局限（诚实记录）

1. 语义分挤在 0.70–0.85，区分度弱 → 有字面匹配的块容易反超
2. 同义泛化有限：实测「钱不够了」找不到「余额」
3. Markdown 符号未清洗，干扰向量
4. `bge-small`（23 MB）区分度不够，**已弃用**

## 六、遗忘机制现状（2026-11-14 体检发现）

**V1.1 的「· 最后提及 YYYY-MM-DD」实际上没落地**：2096 条记忆里 0 条带标记，
所以"≥30 天归档"从来没真正执行过。

**已改用的判据（B 方案）**：
- 文件 **mtime**（多久没被改写）
- **检索命中日志**（`memory-hits.jsonl`，谁被引用过）
- 两者**都**超过 30 天 → 归档候选

归档永远只出候选清单，**删除/搬运前必须确认**。

解压 `memory-v6-20261114.zip` 覆盖 `~/.dsh/memory/` 与 `AGENTS.md`。
检索器是**附加工具**：不跑它 = 回到 V1.3 行为。
