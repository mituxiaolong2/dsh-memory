# 记忆体架构 · V2.1（2026-11-17）

> V2.0 立起「唯一性 / 连续性 / 完整性」的地基；V2.1 修的是**主梁**——
> 把「分层 → 分片 → 元数据 → 调度」这四件事定死，让记忆能长期跑而不变形。

---

## 一、三层 + 一个调度层

| 层 | 加载时机 | 文件 | 分片 |
|---|---|---|---|
| **实时层** | 每轮加载 | `11-近三天.md`、`00-索引.md` | **不分片，只精简** |
| **短期层** | 按需（检索命中/整理）| 20–52 共 12 个文件 | 40,000 字符 |
| **长期层** | 默认不加载 | `70-完成`、`71-归档`、`90-遗忘` | 40,000（遗忘区 100,000）|

**加载顺序固定**：人格核心 → 索引 → 近三天摘要。
越稳定的越靠前，因为前缀缓存从**第一个变化处**断开——摘要每天变，必须排最后。

---

## 二、文件与命名

`<两位类别号>-<类别名>.md`，片号后缀 `<类别号>-<类别名>-<片号>.md`（如 `31-生活-01.md`）。

| 号段 | 归属 |
|---|---|
| `00` | 索引 |
| `10–19` | 实时层 |
| `20–69` | 短期层（事实 / 经历 / 项目 / 知识）|
| `70–99` | 长期层（完成 / 归档 / 遗忘）|

编号管类别、后缀管片；分片切在**条目或小节边界**，绝不劈断多行记录。

---

## 三、条目元数据（旁挂，不进正文）

正文保持干净可读；机器用的元数据放 `memory/.meta.jsonl`，一行一条：

```json
{"id":"m-000001","cat":"教训","file":"50-教训.md","line":12,"ts":"2026-11-17T10:00:00","status":"active","version":1,"keywords":["..."],"hash":"..."}
```

- 必填：**ID / 类别 / 时间 / 状态**
- 关键词、关联、置信度**由脚本生成**（固定词表 + 正文抽取），不手填
- 事实区条目行尾带 `vX@YYYY-MM-DD`，改值 = 覆盖当前值，旧值进该条历史或遗忘区

---

## 四、读写规则

**读**：默认只读 `00-索引`；不确定就检索

```bash
python -X utf8 tools/memory_bm25.py -q "关键词" --top 3
```

命中块几百字，跟文件大小无关；`90-遗忘` 默认不参与（`--all` 才查）。

**写**：出现就立刻落盘。偏好→`20-主人`；约定→`21-约定`（带版本）；踩坑→`50-教训`；
项目/环境变化→`40-项目`；用户说「记住」→ 必须落盘并回报存哪。

**压**：记忆是标签不是原文。写之前问一句「这条明天还用得上吗？」

**整理顺序**：先整体归档 → 再重写当前状态；只删自己写的记忆，永不删用户原话。

**遗忘**：失效 / 过期 / 已完成 / 30 天未被提起 → 原文搬进 `90-遗忘`（带归档日期与原因），
索引删行，**不删除**。

## 五、调度层（谁执行，多久一次）

| 频率 | 动作 | 工具 |
|---|---|---|
| 每天 23:30 | 生成近三天摘要 → 第 4 天下沉（一句话 + 指针进 `31-生活`）| `session_digest.py` + `memory_scheduler.py --daily` |
| 每周日 13:00 | 检索账本 / 漏写检测 / 遗忘体检 / 分片检查 / 完成区按热度归档 | `memory_scheduler.py --weekly` |
| 每月 1 号 | 全局复盘：常青标记、索引核对、架构快照提醒 | `memory_scheduler.py --monthly` |

> 这类系统最常见的死法不是设计错，而是**规则都对、没人执行**。所以调度层是必需件，不是可选项。

---

## 六、和 V2.0 的差异

| 项 | V2.0 | V2.1 |
|---|---|---|
| 元数据 | 写在正文 | **旁挂 `.meta.jsonl`**，正文保持可读 |
| 事实区 | 无版本 | **单值 + 版本**（`vX@日期`）|
| 摘要下沉 | 无规则 | **一句话 + 指针**（≤60 字/天）|
| 完成区归档 | 按时间 | **按热度**（30 天没被命中才归档）|
| 索引 | 降权参与检索 | **退出检索**（只导航）|
| 长期层分片 | 100,000 | **40,000**（只有遗忘区 100,000）|
| 调用调度 | 约定俗成 | **独立调度层**（日/周/月三档）|
| 回忆机制 | 无 | 0 命中时拿关键词匹配长期层，**每次触发写日志** |

## 七、目录示例

```
~/.dsh/
├─ AGENTS.md            # 人格核心（每轮注入）
├─ memory/
│  ├─ 00-索引.md
│  ├─ 11-近三天.md
│  ├─ 20-主人.md 21-约定.md 22-健康.md
│  ├─ 30-时间线.md 31-生活.md 32-见闻.md
│  ├─ 40-项目.md 41-项目档案.md
│  ├─ 50-教训.md 51-技能与工具.md 52-人格札记.md
│  ├─ 70-完成.md 71-归档.md 90-遗忘.md
│  └─ .meta.jsonl        # 旁挂元数据
└─ cache/memory-hits.jsonl   # 检索命中日志（周检复盘用）
```

## 八、最小可用落地

1. `templates/` 里的 16 个文件拷进 `~/.dsh/memory/`，把 `.example` 内容替换成真实内容
2. `AGENTS.md` 用模板改一份，写明「加载顺序 / 红线 / 文件地图」
3. 挂两个定时任务：每天摘要、每周体检（`memory_scheduler.py --daily/--weekly`）
4. 一段时间后看 `memory-hits.jsonl`，把常被命中的文件标 ⭐常青——**别急着加文件，先让已有文件被用起来**
