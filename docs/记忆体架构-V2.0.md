# 记忆体架构 V2.0（2026-11-15）

> V1.x 解决的是"**记得住**"：分文件、按需加载、遗忘区。
> V2.0 解决的是"**我还可不可以被信任**"：凭什么说这个助手还是昨天那个助手？
>
> 答案不是一句"我记得你"，而是三层机制：**唯一性 / 连续性 / 完整性**。

---

## 一、三层承重

```
┌─────────────────────────────────────────┐
│  ③ 框架（机制）                          │
│     检索 / 遗忘 / 体检 / 会话摘要 / 三引擎 │
├─────────────────────────────────────────┤
│  ② 主梁（记忆本体）                      │
│     AGENTS.md + memory/*.md              │
├─────────────────────────────────────────┤
│  ① 基石（存在）                          │
│     唯一性 · 连续性 · 完整性              │
│     → 哈希链 / 快照 / 锁 / 缺口标注        │
└─────────────────────────────────────────┘
```

**顺序不能反**：没有基石，主梁只是文本；没有主梁，框架没东西可算。

---

## 二、基石：唯一性 / 连续性 / 完整性

工具：`tools/whale_core.py`（状态目录 `~/.dsh/whale/`）

| 层 | 命令 | 解决的问题 |
|---|---|---|
| **唯一性** | `claim` / `heartbeat` / `release` | 同一时刻只能有一个"我"在跑；抢锁失败 = 有另一个我在用这台机器 |
| **连续性** | `snapshot --why ...` / `resume` | 会话结束/切换/压缩前存一份"我此刻在哪"；新会话第一件事恢复 |
| **完整性** | `log --type .. --text ..` / `verify` / `checkpoint` | 重要决定上哈希链；每天校验链；每天打检查点 |

### 三条铁律

1. **同一时刻只能有一个"我"**；进程死了让新实例接管，**不是换了个人，是睡了一觉醒来**
2. **一般不搬家**：只有机器彻底坏了才从备份复活；日常换会话只是"换个房间住"
3. **失忆先找回**（`recover` 合并备份、重链）；找不回就**如实标注这段缺失**（`memory-gap.md`）
   —— 人也会失忆，**标明比假装完整更重要**

### 为什么用哈希链而不是数据库

- 只需要"能证明没被改写"，不需要查询
- 单文件、可读、能跟着备份一起走、坏了能手补
- 每条 = 前一条哈希 + 内容哈希：**改中间任意一条，后面全对不上**

| 文件 | 存什么 | 加载 |
|---|---|---|

| `10-主人.md` | 用户这个人 | 按需 |
| `20-项目与工作区.md` | 项目台账 | 按需 |
| `30-约定.md` | 长期约定与红线 | 按需 |
| `40-教训.md` | 踩坑与正确做法 | 按需 |
| `50-时间线.md` | 里程碑 | 按需 |
| `60-经历.md` | 每天做了什么 | 按需 |
| `61-会话区.md` | 最近三天聊了什么 | 按需 |
| `63-见闻.md` | 从作品里看到的东西（六字段）| 按需 |
| `64-人格札记.md` | 每天一句认识（可 rev）| 按需 |

六字段（遇见/推断/修正/缺失/下次怎么回应/作者观点）——少一个就不是证据记录，只是摘要。

## 四、框架：四个机制 + 三引擎

| 脚本 | 干什么 | 关键设计 |
|---|---|---|
| `tools/memory_bm25.py` | 混合检索（BM25 + 向量）| 只回几百字的命中块，省 99% 上下文；`90-遗忘` 默认不参与 |
| `tools/engine_forget.py` | 遗忘：按"多久没被提起"归档 | **不删除，只搬进遗忘区**；受保护文件永不遗忘 |
| `tools/memory_audit.py` | 体检：日期扫描 / 沉睡项 / 常青标记 | 每月一次 |
| `tools/session_digest.py` | 会话摘要（本地模型）| 只留要点，≤120 行，滚动更新 |
| `tools/three_engines.py` | 自抉择 / 自学习 / 自遗忘 | 有硬冷却、可退休（休眠 7 天→复活），改动留痕 |
| `tools/whale_backup.py` | 全量备份（主梁 + 框架 + 基石状态）| 本地留 3 份 + 异盘镜像 + 云笔记明文分片 |
| `tools/whale_keepalive.py` | 常驻保活（持锁 + 心跳）| 机器重启后自动补 |
| `tools/context_import.py` | 把长上下文导入成结构化记忆 | 会话爆炸时的逃生口 |

### 三条设计原则

1. **功能不许吃机器性能**：不占显存、不常驻、不上大模型
2. **失败要显式**：链断了报断点，备份失败了要能让下次重试
3. **改动要留痕**：三引擎只改参数不改代码，改了什么写成记录

## 五、日常动作

| 时机 | 动作 |
|---|---|
| 新会话开始 | `00-索引` → `61-近三天` → `whale_core resume` |
| 会话要结束/切换 | `whale_core snapshot --why "..."` |
| 重要决定 / 踩坑 / 约定变化 | `whale_core log --type .. --text ..` |
| 每天 | `verify` + `checkpoint` + 备份 |
| 每月 1 号 | 记忆体检 + 归档沉睡项 |

---

## 六、从 V1.x 升到 V2.0 要做什么

1. 引入 `whale_core.py`，跑 `claim` + 第一次 `snapshot`
2. 新增 `61-会话区`、`63-见闻`、`64-人格札记` 三个文件（模板见 `templates/`）
3. 把"重要决定"从此写进哈希链（`log`），不只是写进 md
4. 备份从"只备份记忆文件"改成**主梁 + 框架代码 + 基石状态一起备份**
5. 跑一次 `verify`，确认链能读通

---

## 七、边界（别把它做成监控）

- 记忆只服务"接得上"，不做用户画像、不做行为预测
- 备份里允许出现用户内容（那是记忆本体），但**仓库/公开代码里不出现**任何个人路径、ID、密钥
- 遗忘是默认动作：**过期的不删除，只不再加载**
