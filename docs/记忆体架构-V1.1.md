# 记忆体架构 V1.1 · 压缩与遗忘规则改版

> 基于 V1.0，**只改压缩策略和遗忘触发条件**，文件结构与加载策略不变。
> 本文件为**通用版**，不含任何个人信息。

---

## 一、这次改了什么（一句话）

**按需读取的文件不再卡 150 行（放宽到 1000 行），遗忘触发从"文件超长"改成"条目 30 天没被提起"。**

| 项 | V1.0 | **V1.1** |
|---|---|---|
| 按需文件行数上限 | 150 行 | **1000 行** |
| 什么时候动某条记忆 | 文件超长就整理 | **超过 1 个月没被提起** → 丢遗忘区 |
| 反复提起的 | 无特殊处理 | **持续保留**（引用次数越多越优先留）|
| 常加载文件（索引/人格）| 小 | **仍然要小**（不变）|

---

## 二、文件分两档（关键区分）

### 第一档：常加载（必须精简）

| 文件 | 上限 | 为什么 |
|---|---|---|
| `AGENTS.md` | **≤200 行 / ≈10 KB** | 每轮注入，涨一句就是每轮多花 token |
| `00-索引.md` | **≤150 行** | 开局必读，每条只许一句话 |

### 第二档：按需读取（可以大）

| 文件 | 新上限 |
|---|---|
| `10/20/30/40/50` | **≤1000 行** |
| `90-遗忘.md` | 不限（不加载）|

**为什么可以大**：这些文件**只在相关话题时才读**，读的人会按小节定位。
行数不是浪费——**真正的浪费是"没用的东西也留着，还指望下次会读"**。

## 三、遗忘触发：从"超长"改成"30 天没被提起"

### 规则

```
一条记忆被写进文件时，带一个「最后提及」日期
        ↓
每次它影响过一次输出 → 刷新日期
        ↓
某条 ≥30 天没被提起 → 搬进 90-遗忘.md（原文保留，不删）
        ↓
被反复提起（≥3 次）→ 打「⭐常青」标记，优先保留
```

### 三种状态

| 状态 | 判据 | 处置 |
|---|---|---|
| **活跃** | 30 天内被提及过 | 留在原文件 |
| **常青** | 累计引用 ≥3 次，或属"人格/红线/核心事实" | **永不遗忘**，加 `⭐常青` |
| **沉睡** | ≥30 天未被提及 | 搬进 `90-遗忘.md`，原文 + 归档日期 + 原因 |

### 怎么记"最后提及"

写在条目末尾：

```markdown
- 用户 2026-11-10 说缴费窗口是 11/14–16 · 最后提及 2026-11-11
```

**为什么不做复杂系统**：一个日期字符串就够，不需要数据库、不需要脚本依赖。
**代价**：得靠 agent 每次引用时顺手更新——**这是纪律问题，不是技术问题**。

### 每月体检（每月 1 号，5 分钟）

1. 扫五个按需文件，看每条 `最后提及` 日期
2. ≥30 天的 → 原文搬进 `90-遗忘.md`（带归档日期 + 原因）
3. `00-索引.md` 删掉指向它的那行
4. 引用 ≥3 次或红线类的 → 标 `⭐常青`
5. 在 `50-时间线.md` 写一行：「本月归档 N 条」

**以后可脚本化**（扫日期、生成待归档清单），但**判断"该不该留"仍要人/agent 看**。

## 四、什么算"被提及"

| 动作 | 算不算 |
|---|---|
| 在对话里引用这条记忆回答用户 | ✅ 算，刷新日期 |
| 因为这条记忆做了某个决定 | ✅ 算 |
| 用户主动问起相关的事 | ✅ 算 |
| agent 内部读了一遍但没用上 | ❌ 不算（读不等于用）|
| 每月体检时扫到 | ❌ 不算 |

**判断标准：这条记忆有没有真的影响过一次输出。** 没影响过，就是沉睡的。

## 五、完整差异表

|---|---|---|---|
| 1 | 按需文件上限 | 150 行 | **1000 行** |

## 六、不变的部分

- 文件结构：七个文件 + 人格
- 加载策略：开局只读索引，细节按需，绝不整份加载
- 遗忘本质：**不删除，只不再加载**
- 架构快照：改动就打 zip
- 四重备份：现役 → 主副本 → 异盘 → 异地
- 写入规则、三不原则

## 七、一句话

> **V1.0 管"别让记忆变胖"，V1.1 管"只有还会被想起的才留着"。**
> 胖不是问题，**没人再提的东西占着位置**才是问题。
